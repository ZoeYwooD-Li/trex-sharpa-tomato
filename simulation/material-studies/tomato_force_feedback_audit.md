# Tomato soft-body force feedback: audit and staged progress

## Scope and scene safety

The original tomato scene files were not changed. Work is limited to the separate `outputs/tomato_fem_*` files and a new public-material reference directory. The original Newton project and Isaac smoke-test scenes remain untouched.

## Audit of current implementation

The replayable tomato curve in `outputs/tomato_fem_results` is generated by `outputs/tomato_fem_compression.py`, a SciPy sparse quasi-static tetrahedral FEM, not live PhysX. Its model is small-strain homogeneous isotropic linear elasticity; contact uses nodal penalty springs. Units in the script are SI (m, kg, N, Pa). The generated mesh is 698 nodes, 1,958 tetrahedra and 1,280 surface triangles. E is swept over 0.2, 0.8 and 2 MPa, ν=0.42, and penalty=1e7 N/m. Radius 17.2 mm and mass 20 g originate in the older project settings and are not measured tomato properties.

The existing solver fixes the lowest tomato node in all three translations, so the z support can be carried by a kinematic pin rather than floor contact. Its floor and platen active sets only grow, so a penalty contact node cannot detach. Therefore the old zero-penetration output and its platen force are not reliable physical validation. At 0.8 MPa the old script reports 1.98, 7.36 and 23.15 N for 0.5, 1 and 2 mm, but these are model predictions with the above constraint issue, not ground-truth force labels. The playback USD is baked FEM output, not a live PhysX simulation.

A separate attempt to remove the bottom z pin and allow unilateral active-set release was run. It did not converge reliably: contact-node switching oscillated during platen compression. That attempt was reverted; the legacy script was restored and its output was reproduced in `outputs/tomato_fem_legacy_repeat`. No nonconvergent contact edit is left as the current implementation. This result blocks a claim that the tomato solver is now physically validated.

## Public-data force reference completed

The Zenodo compression archive has been downloaded to `outputs/public_material_reference/source_uniaxial_compression.zip`. A conversion script creates force–displacement references for the standard 28.6 mm × 12.5 mm cylinder at 0.5, 1, 2 and 3.125 mm. It converts engineering stress to force with the initial area. Ten materials and all available specimen traces are retained; Cheetah only reaches 15% strain in this source.

For the 25% point, the processed raw means reproduce representative paper values closely: Ecoflex 00-20 0.0442 MPa vs 0.044 MPa reported; Ecoflex 00-30 0.0553 vs 0.056 MPa; Dragon Skin 20 0.196 vs 0.20 MPa; Dragon Skin 30 0.284 vs 0.28 MPa. Differences reflect finite replicate count / data export rounding. This checks the source parsing and stress scale, and the area conversion has units N/mm² × mm² = N. It does not validate the tomato FEM or tell us which elastomer matches tomato.

## Next implementation gate

Isaac Sim 5.1's deformable-material API exposes Young's modulus, Poisson ratio, density, and damping rather than the public dataset's multi-parameter Ogden model. Its volume-deformable view does document element-wise stress tensors. This gives an Isaac-compatible first gate: fit a linear effective E only over the small-strain range, run a standard cylinder coupon, and estimate platen reaction from the stress field integrated over the platen-facing boundary. First verify the stress measure, units, normal orientation, and integral against the known coupon load and global balance; the stress array alone is not yet a validated force sensor. The user-facing `ContactSensor` route cannot be assumed to provide deformable rigid-contact force.

If the coupon simulation cannot reproduce the nonlinear measured curve with the Isaac material model, keep Isaac for geometry/control and use a hyperelastic solver for material-force supervision. Use at least three elastomer stiffness levels; add relaxation holds only with a viscoelastic model. After the coupon gate passes, create a separate tomato scene and report its forces explicitly as extrapolated material-model predictions. Keep damage / rupture unclaimed until an appropriate measured failure dataset and failure law exist.

## Reproduction

```bash
/path/to/local/anaconda3/envs/RoboDojo/bin/python outputs/build_public_material_reference.py
/path/to/local/anaconda3/envs/RoboDojo/bin/python outputs/tomato_fem_compression.py --show-meshes --output outputs/tomato_fem_legacy_repeat
```

The first command rebuilds the public reference. The second only reproduces the legacy tomato prediction; it is not a physical validation run.

## GPU error follow-up (2026-11-07)

The user ran the old split-mesh diagnostic and reproduced `Unable to copy data from host to device for collElementIndicesBuffer`. On the RTX 5090, a separate scene using a **shared simulation/collision tetra mesh** created the PhysX volume-deformable view and read 163 nodes without that CUDA error. A headless run completed and wrote `outputs/isaac_tomato_gpu_deliverable/`.

For that smoke deliverable, `E=5 MPa`, `nu=0.42`, damping 0.005, dt 1 ms, 128 position iterations, contact offset 0.2 mm and rest offset zero were used. These are demonstrator settings, not tomato calibration. A 0.2 N gravity-equivalent command over 0.1 s produced a peak 2.91% bounding-height reduction and recovered to near zero after release; minimum node z was −0.0017 mm. This demonstrates GPU soft-body stepping and node readback. It does not validate the material response or measure contact force.

`outputs/isaac_tomato_live_sharedmesh.py` is the runnable isolated version. It records commanded gravity-equivalent load and deformation, and explicitly leaves `measured_contact_force_N` null. The Isaac Sim 5.1 stress/index readback path remains unusable in this environment, and the direct kinematic platen control path stalled, so an actual platen reaction force remains blocked. The live run command and parameter caveats are in `outputs/isaac_tomato_gpu_deliverable/README.md`.
